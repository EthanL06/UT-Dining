# UT Dining

pnpm + Turborepo monorepo for the UT Dining iOS/Android app and its services.

This file is the agent guide for every tool (`CLAUDE.md` imports it). Each app with its own rules has an `AGENTS.md` too: `apps/mobile`, `apps/dashboard`, `apps/scraper`. Code comments are not allowed in this repo, so context that would go in a comment goes in these files, a README or the PR description.

## Start here

1. `make verify` after every change: Biome on the changed files, the comment check, typecheck and tests of only the affected packages, then a list of what else to verify for this diff. About 3 s.
2. `git push` runs the pre-push hook: the CI checks scoped to what changed, about 3 to 8 s. `make check` runs everything, the same as CI.
3. Read `.agents/recipes/README.md` for gotchas in your area. Cloud sessions: read `.agents/recipes/cloud-sessions.md` first (GitHub writes, screenshots, Supabase projects, generated type conflicts).
4. Recurring flows (merging, OTA vs EAS builds, dev and prod migrations, prod data changes, screenshots, the cutover) are step by step in `.agents/runbook.md`. Follow it, and keep it true: when you change or discover how one of those flows works, update the runbook in the same PR.

## Layout

- `apps/mobile`: Expo SDK 58 app (React Native 0.88, React 19, New Architecture only; Expo Router, NativeWind, Drizzle + expo-sqlite, TanStack Query, Zustand, MMKV). Needs a development build, not Expo Go. EAS config lives here.
- `apps/dashboard`: admin dashboard (Next.js 16, Mantine, Supabase SSR auth). Deployed on Vercel.
- `apps/website`: public site, changelog and privacy policy (Next.js 16 on Vercel, server-rendered with ISR, Tailwind 4). `WEBSITE_STATIC_EXPORT=1` builds the static copy GitHub Pages serves under `/ut-dining-website`, which the App Store privacy link still points at; keep `/privacy-policy/` unchanged.
- `apps/cli` (`@ut-dining/cli`): command line version of the dashboard for agents. See "Dashboard data" below.
- `apps/scraper`: daily menu scraper. Plain ESM TypeScript run directly by Node (no build). Runs twice a day (1 AM and 9 AM Central) from `.github/workflows/scraper.yml` (GitHub Actions), retrying once 10 minutes after a failure. Supabase RPC uploads retry up to 3 times. The same workflows then sync the hours and payment methods of UT-run restaurants, cafés, markets and food trucks from UT's sites (`pnpm --filter @ut-dining/scraper places`); private vendors stay manual.
- `packages/core` (`@ut-dining/core`): pure domain logic shared by the app, the dashboard and the website (service hours, open/closed status, Central-time dates, payment methods, sync planning). No React, React Native or database code here; Vitest tests live next to the source. Run with `pnpm --filter @ut-dining/core test`. New pure logic goes here when more than one app can use it.
- `packages/supabase` (`@ut-dining/supabase`): generated Supabase types. Regenerate with `make db-types`; never hand-edit.
- `packages/tsconfig` (`@ut-dining/tsconfig`): shared TypeScript presets.
- `supabase/`: the single Supabase project (migrations, seed, Deno edge functions).

## Commands (run from the repo root)

The `Makefile` is the front door. `make` prints every target. Every target is non-interactive, idempotent and prints `==>` steps with `ok`, `warn` and `fail` lines, so it is safe for agents.

- `make setup`: one command for a fresh clone or a stale one: Node, pnpm, deps, git hooks, `.env.local` files, local Supabase (Docker), a few days of scraped menus. Re-running keeps existing env files and data. `DB=local|dev|none`, `SEED=0`.
- `make doctor`: checks the whole setup and exits 1 on a real problem (including any app pointing at production). Run it first when something is off.
- `make verify`: the fast, scoped check (see Start here). `BASE=<ref>` changes the base from `origin/staging`.
- `make check`: Biome + typecheck + tests of everything. `make pre-push`: what the pre-push hook runs (see Git hooks). `make fix`: Biome safe fixes. `make check-comments` fails on added code comments (the pre-commit hook runs it on the staged diff). `make check-state` fails on implicit state machines (see Conventions).
- Tests: Vitest in `packages/core`, `apps/scraper`, `apps/cli`, `apps/dashboard` (pure helpers such as `lib/status/*.test.ts` and `components/**/*-utils.test.ts`) and `apps/mobile` (pure helpers in `apps/mobile/utils` only, `*.test.ts` next to the source; anything that imports React Native or MMKV cannot run there). One file: `pnpm --filter @ut-dining/mobile exec vitest run utils/filter.test.ts`.
- `make typecheck`: TypeScript 7 via the `tsgo` alias; `typescript` itself stays on 6.x because Expo tooling needs the JS API.
- `make dev` (dashboard :3000, website :3001, Metro :8081), or one at a time: `make dashboard`, `make website`, `make mobile`, `make ios SIM=<name or UDID>`, `make scrape`.
- Database: `make db-up`, `make db-down`, `make db-status`, `make db-reset`, `make db-migrate`, `make db-new NAME=x`, `make db-types`, `make db-check`, `make db-seed DAYS=3`, `make db-fixtures`, `make db-sample`, `make db-fresh`, `make db-psql ARGS='-c "select 1"'`. Read the real URLs from `make db-status`: when another project holds 54321, `make db-up` moves the stack and saves the ports in the gitignored `supabase/.env`. Never edit ports in `supabase/config.toml`.
- Test data: `make db-fresh` resets local Supabase and loads sample menus and edge-case places (empty and missing menu days, a force-closed hall, places without map pins, colloquial names, hours that end at 23:59 or start at 00:00, dishes that differ between today and tomorrow in Central time) in about 40 s with no network. Test against it instead of the hosted dev project. Scenarios and how to add one: `scripts/dev/sample/README.md`; a new edge case you hit belongs there.
- iOS: `make sim`, `make sims`, `make e2e SIM=<UDID> ARGS="--shards 3"`.
- Ethan's Mac is shared by parallel threads, so never boot or drive one of his own simulators. `make sim-lease OWNER=<thread>` clones the "UT Dining golden" simulator (development build installed) into your own and prints `<UDID> <slot>`; pass that UDID as `SIM=` and use Metro port `8090+slot`. Release your simulator the moment its work is done, not at the end of the thread (Ethan's rule, after a leftover lease crashed the app on his Mac): `make sim-release` releases every lease taken from the current worktree (or `SIM=<UDID>`, `PR=<n>`, `BRANCH=<name>`), stops its Metro (port `8090+slot`), fixture server and Maestro, then shuts the simulator down and deletes it. `make sim-leases` shows who holds what. `make merge-pr` releases every lease of the PR and branch it merged. Leases record the PR (`OWNER=pr-<n>` or `ARGS="--pr <n>"`), branch and worktree they came from, so the launchd sweeper (`make sim-sweeper`, installed once on the Mac; `make sim-sweep ARGS=--dry-run` shows what it would do) releases them every 5 minutes when the PR is merged or closed, the worktree is gone, the lease passed its 2-hour TTL, or the simulator was idle for 15 minutes. Idle means no process other than Metro (Maestro, xcodebuild, simctl, a Python or Node driver) names the UDID and the lease was not renewed; a Metro left running by `make ios SIM=<UDID>` does not count, so between steps that take longer than 15 minutes run `scripts/dev/sim-lease.sh renew <UDID>`. It also stops orphaned Metro on unleased slot ports and Maestro or Xcode processes aimed at deleted simulators. `make sims-idle` shuts down every booted simulator nobody uses, and `make clean` runs it too. Slots: one per 8 GB of RAM (4 on Ethan's Mac), minus every other booted simulator, and none while the load average is over twice the core count, so an overloaded Mac sends `make pr-screenshots` to CI instead of timing out; leases expire after 2 hours. The golden simulator must hold a development client (`EXDevLauncher.bundle`), never a release build. After a native change, `scripts/dev/sim-lease.sh golden --from <UDID or .app>` refreshes the golden simulator.
- Worktrees: `make worktree NAME=feat-x` creates `.worktrees/feat-x` from `origin/staging` with env files and deps. All worktrees share one local Supabase.
- Cleanup when you are done: `make clean` (Metro, E2E simulator clones, clean and pushed worktrees, caches) and `make stop` (also local Supabase and every booted simulator). On Ethan's Mac, shut down only simulators you booted.
- `pnpm --filter @ut-dining/<app> <script>`: run one package's script. The root `pnpm` scripts still work.
- New dev scripts go in `scripts/dev/` and get a Makefile target plus a line in `make help`. They must run on macOS bash 3.2. Every script a person or agent runs has a target; only `scripts/claude-session-start.sh` (the SessionStart hook) and the sourced `scripts/dev/lib.sh` and `scripts/dev/sim-lib.sh` do not. `make test-sims` tests the simulator scripts against a stubbed `simctl` on any OS, without booting anything; CI runs it.

## Git hooks

Lefthook (`lefthook.yml`) installs the hooks from the root `prepare` script, so `pnpm install`, `make setup` and the cloud SessionStart hook all set them up. `make doctor` warns when one is missing; `pnpm exec lefthook install` fixes it. They exist to catch CI failures before a push, so each mirrors a CI step.

- pre-commit, on staged files, in parallel (about 2 s): Biome with `--write --error-on-warnings` like CI (YAML included), the no-comments check, and `scripts/dev/check-staged.sh` (no `.env` files, keys or certificates, likely secrets such as `sb_secret_`, GitHub tokens or JWTs, or files over 1 MB).
- commit-msg: commitlint (conventional commits).
- pre-push (`scripts/dev/pre-push.sh`, `make pre-push`): refuses pushes to `main` or `staging`, then runs in parallel against the merge base with `origin/staging`: `biome ci --error-on-warnings` on the whole repo (catches rules that arrived with a staging merge), comments, file size, state machines, and `turbo run typecheck test --affected`, which the local Turborepo cache makes instant for unchanged packages. It adds the lockfile check when a `package.json` changed, the Deno edge function check when `supabase/functions` changed, and the file checks of `make db-check` (`STATIC=1`, no Docker) when `supabase/` changed. Docs-only pushes skip it (`scripts/ci/docs-only.sh` decides: only `*.md`, `.agents/**` and `LICENSE`, except `apps/website/content/`, which the website renders). Measured: about 3 s warm, 5 s for a cold app change, 8 s for a `packages/core` change. Builds, the Postgres migration check and E2E stay in CI.
- It checks the working tree at `HEAD`, so commit or stash first for an exact result.
- Never bypass a hook to get past a failure; fix it. `git push --no-verify` (or `LEFTHOOK=0`) is only for a push where the hook itself is wrong, and the PR says why. `ALLOW_PROTECTED_PUSH=1` allows a push to `main` or `staging` and is only for Ethan.

## Conventions

- No code comments in code you write, workflow YAML and shell included (`biome-ignore`, `@ts-expect-error` and `state-machine-ok:` directives are fine). There are none in the repo, and `make check` and CI fail on any (`scripts/dev/check-comments.sh --all`, which parses TypeScript, JavaScript and CSS); Lefthook checks the staged diff. `node scripts/dev/comments.ts --write` removes them. Only `supabase/config.toml` (the Supabase CLI template), SQL migrations and generated files are exempt.
- Lint is Biome only (`biome.json`), and warnings count: `make check`, `make lint`, `make verify` and CI all run with `--error-on-warnings`, so an unused `biome-ignore`, an unsorted Tailwind class list or any other warning fails the build. `make fix` applies the safe fixes. Rules that are errors on purpose, so agents get a clear failure instead of a review comment:
  - Types: no `any` (explicit or implicit `let`), no non-null `!`, no `@ts-ignore` (use `@ts-expect-error`), no `enum` or `namespace`, `import type`/`export type` for type-only imports.
  - Hygiene: no unused imports, variables or function parameters (prefix with `_` when a signature needs it), `===` only, `const` when never reassigned, no `var`, no reassigned parameters, throw only `Error`s, no `else` after `return`, template literals over string concatenation, `node:` prefix for Node built-ins, `T[]` array types.
  - Size: no source file over 500 lines (`style/noExcessiveLinesPerFile`, backed by `scripts/dev/check-file-size.sh` in `make check`, `make verify` and CI, because Biome 2.6.9 misses some TSX files). When a change would push a file past it, split the file by responsibility in the same PR (sections into components, pure helpers into a `*-utils.ts` with tests) instead of raising the cap. Generated files are exempt.
  - Promises: no floating promises (`nursery/noFloatingPromises`) and no promise passed where a void callback is expected (`nursery/noMisusedPromises`). Await it, add a `.catch` that logs, or mark a deliberate fire-and-forget with `void` when the callee handles its own errors.
  - Switches: a `switch` on a union must handle every member or have a `default` (`nursery/useExhaustiveSwitchCases`). Pairs with the explicit state machine rule below: render a status union with a `switch`, and adding a member fails lint everywhere it is not handled.
  - React hooks: `useExhaustiveDependencies` is an error. Add the dependency, or use `useEffectEvent` for a callback that should not re-run the effect.
  - Time zones (`biome-plugins/no-device-time-zone.grit`): app and package code never reads the device time zone. `getHours`, `getDay`, `getDate` and the other `Date` getters and setters, `new Date(year, month, day)`, `toLocaleDateString`/`toLocaleTimeString` without a `timeZone`, `toLocaleString` on a date without one, and `Intl.DateTimeFormat` without one all fail. Use `@ut-dining/core`: `toCentralTime` (date key, weekday, Hhmm), `formatCentral(instant, options)`, `formatCentralDateKey('YYYY-MM-DD', options)`, `daysBetweenDateKeys`, `formatHhmm`. In the app, `date-fns` and `date-fns-tz` are imported only by `utils/date.ts`. `packages/core/src/central-time.ts`, `apps/mobile/utils/date.ts` and tests are exempt.
  - Icons (`biome-plugins/no-icon-barrel.grit`): import icons by name. A namespace import (`import * as Icons`) or `export *` of `lucide-react-native`, `lucide-react` or `@tabler/icons-react`, or the `icons` map from lucide, bundles every icon and undoes the tree shaking from the lucide Babel plugin.
  - Logging: no `console` anywhere except the loggers (`log` from `apps/mobile/utils/log.ts`, `apps/dashboard/lib/log.ts`, `apps/website/lib/log.ts`, `apps/scraper/src/log.ts`, `supabase/functions/_shared/log.ts`) and the dev scripts in `scripts/`, which print to the terminal on purpose. The CLI writes through `apps/cli/src/output.ts`.
  - Custom rules are GritQL plugins in `biome-plugins/`, listed under `plugins` in `biome.json` with the files they apply to. They run in `make lint`, `make verify`, the pre-commit hook and CI like any other rule.
  - Tests: no `.only` or `.skip` left in a test file.
  - Dependencies: every import must be listed in that package's `package.json` (pnpm's isolated `node_modules` breaks undeclared ones at runtime).
  - Unused code: `make check-unused` runs [knip](https://knip.dev) (config in `knip.json`) and fails on an unused file, export or dependency, and on an import of a package the workspace does not list. It runs in `make verify`, `make check`, the pre-push hook and CI. Delete what it reports rather than ignoring it; an export used only in its own file is fine. `ignoreDependencies` holds packages that are used outside TypeScript (Tailwind CSS imports, Babel and NativeWind peers, the Expo tunnel) and the native modules `expo-status-bar` and `@expo/vector-icons`, which wait for the next native build to be removed.
  - Mobile (`apps/mobile`): images only through `Image` from `~/components/ui/Image` (expo-image with NativeWind `className`), never `Image` or `ImageBackground` from `react-native`; haptics only through `~/utils/haptics` (never import `expo-haptics`), and only `services/` imports Supabase (`~/utils/supabase` or `@supabase/supabase-js`); screens, components, hooks and stores read the SQLite cache. Raw strings must sit inside a `<Text>` (`noReactNativeRawText`), and `Text`/`TextInput` come from `~/components/ui/Text`, never `react-native`. More in `apps/mobile/AGENTS.md`.
  - Fix the code. Do not add a `biome-ignore` unless the rule is wrong for that line, and say why in the ignore. A new rule goes in `biome.json` only when the repo passes it, or the same PR fixes every violation.
- State machines are explicit. When two or more pieces of state together describe one status (`isLoading` + `error` + `data`, `selecting` + `selectedIds`, `done` + `message`, a modal's `opened` + `editingItem`, a nullable value whose `null` means both "still loading" and "not found"), replace them with one discriminated union (`{ status: 'loading' } | { status: 'ready'; item } | { status: 'missing' }`) or one string-literal status, and derive the booleans from it. When a screen's state comes from several queries, compute it in a pure function that returns a union and has a test (`apps/mobile/utils/homeView.ts`, `apps/mobile/utils/menuList.ts`). Render with a `switch` or `kind` check on the union, not with chains of boolean checks. One independent boolean (a toggle, a form's `isSubmitting`) is fine. Review every new `useState`, store field and `let` flag against this rule. `make check-state` (also in `make verify`, `make check` and CI) enforces the common cases: it fails on two or more boolean `useState` in one component or hook, and on a `useState` named like a status (`status`, `state`, `phase`, `mode`, `step`, `stage`, `view`) that is typed as plain `string`. For a real exception, put `// state-machine-ok: <reason>` on the line above the `useState`; it is the one comment besides `biome-ignore` and `@ts-expect-error` that the no-comments check allows, and the reason is required.
- Loading is its own state, never the empty state. While data is still loading (a query has not returned, the first sync has not finished, a debounced search has not caught up with what was typed), show a loading view (skeleton rows or a spinner), not "No results", "Nothing here" or any empty-state copy or button. Model it as its own `loading` (or `pending`) member of the screen's union and decide it in the pure view function with a test, so "no data yet" and "no data" can never render the same. Examples: `apps/mobile/utils/mapSheetView.ts` and `components/map/SkeletonRows.tsx`.
- Scroll only when content overflows, and never let scrolling content hard-clip under a header or sheet edge: pin the header outside the scroll view and show a divider once it scrolls. In the app, use `OverflowScrollView` (see `apps/mobile/AGENTS.md`).
- No AI attribution in commits, PR bodies or comments: no `Co-Authored-By` or session trailers, no "Generated with" lines.
- PRs target `staging` and are squash merged with a hand-written message. Ask Ethan before merging. Once he says yes to that PR, merge it yourself with `make merge-pr PR=<n> TITLE="<conventional subject>" BODY_FILE=<file>`: it refuses PRs not based on `staging`, drafts, conflicts and AI attribution, and pins the merge to the head you saw. The rest of the steps (mergeability check, follow-ups) are in `.agents/runbook.md`. Only Ethan promotes `staging` to `main`, which ships production.
- Conventional commits (enforced by commitlint through Lefthook) and conventional PR titles (the "Conventional PR title" check, required on `main`). Branches are `<type>-<kebab-description>`, e.g. `feat-meal-reminders`.
- A PR that changes UI includes screenshots (both themes for the app), every image inline in the PR body, never a link to an index. For the app, run `make pr-screenshots PR=<n> SCREENS="home map"` on Ethan's Mac: it leases its own simulator, takes both themes of the current worktree, pushes them to `assets/pr-<n>` and replaces the Screenshots section of the PR body. It falls back to the CI `screenshots` label by itself when every slot stays busy for 5 minutes or no simulator has the development build. From a cloud session when the Mac is unreachable, run `scripts/qa/pr-screenshots.sh <n> --ci`; the CI run embeds the images in the body too. A screen not in `apps/mobile/e2e/screenshots.txt` can be passed as `name=<deep link path>`. CI also takes a full set after every merge to `staging` that touches the app, on `assets/staging`, without blocking anything.
- Report build, preview, PR and OTA state only from live data: `make status` or the snapshot it publishes (see "Reporting state" in `.agents/runbook.md`), never from memory or an earlier note.
- Test only against local Supabase or the hosted dev project. Never point a test, build, script or session at production.
- Migrations must be backwards compatible, because the shipped app and the deployed dashboard keep running against the new schema: add columns, tables and functions; do not drop, rename or change the type of anything existing code reads. Never edit a migration that is already on `staging`.
- `make db-check` (and the "Migration safety and types" job in `.github/workflows/database.yml`, a required check on `main`) proves that: it applies the `BASE` migrations (default `origin/staging`) to a throwaway Supabase Postgres, applies the new ones on top like production will, and fails on a dropped or renamed table, view, column, function, enum value or policy, a type change that is not a widening, a column that became `NOT NULL`, a new `NOT NULL` column without a default, or a privilege `anon`, `authenticated` or `service_role` lost. Changed policies, new constraints and newly enabled RLS are warnings to check by hand. It also fails when a migration already on `BASE` was edited, renamed or deleted, when a new one sorts before the newest on `BASE`, when a fresh reset with `supabase/seed.sql` fails, or when `packages/supabase/src/database.types.ts` differs from what the migrations generate. It never touches the shared local stack, hosted dev or production, and takes about a minute. A deliberate breaking change needs Ethan's OK and the `breaking-migration` PR label, which turns those failures into warnings.
- Biome formats and lints everything: single quotes, 2 spaces, 100 columns.
- Shared versions go in the `catalog:` in `pnpm-workspace.yaml`.
- PR screenshots go on an orphan `assets/<topic>` branch. Include both `apps/dashboard/vercel.json` and `apps/website/vercel.json` containing `{ "git": { "deploymentEnabled": false } }` in that branch, or Vercel tries to build it, fails because the app folder is missing, and emails Ethan. `.agents/recipes/cloud-sessions.md` has the commands.
- Vercel builds the dashboard and the website only when needed, to stay under the free plan's 100 deployments a day. Both `vercel.json` files run `scripts/vercel-ignore.mjs`: a preview builds only for `staging` or a branch with an open PR, and any build is skipped unless the diff touches the app, a workspace package it depends on, or a root build file (`package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, `turbo.json`, `.node-version`). The diff base is the last deployed commit, or where the branch left `staging` when that commit is gone. A push made before its PR exists builds nothing, so push again after opening the PR to get a preview. When a new app or package path should trigger a build, update the script.
- pnpm uses its default isolated `node_modules`. The app must list every package it imports directly (for example `react-native-css-interop`, which NativeWind's JSX runtime needs).
- Dependencies update through Renovate (`renovate.json`): weekly PRs into `staging` on Monday mornings (Central), with patches grouped in `renovate/patch` and merged by Renovate once every check passes, minors grouped for review, mobile patches and minors in their own PR that never auto-merges, and majors one PR each. Expo SDK packages and the native packages the SDK pins are left to `npx expo install`, and TypeScript stays on 6.x. Change the rules in `renovate.json` rather than closing Renovate PRs by hand. GitHub Actions are pinned to commit SHAs with a trailing `# vN` tag marker (`uses: actions/checkout@<sha> # v7`); Renovate reads that marker to keep the pin current, so it is the one allowed YAML comment. Pin new actions the same way.
- Docs-only PRs (the same `scripts/ci/docs-only.sh` rule) merge in minutes: `ci.yml` and `database.yml` still run and report success, so branch protection passes, but skip install, lint, typecheck, tests, builds and the migration check; CodeQL ignores Markdown-only PRs. Pushes to `staging` and `main` always run everything. When a new kind of non-code file appears (for example docs in another format), update that script, not the workflows.
- Security checks on PRs: CodeQL (`codeql.yml`) and `dependency-audit.yml`, which fails only when the PR adds a high or critical advisory that the base branch does not already have. `branch-cleanup.yml` deletes a PR's branch when it merges and sweeps older merged branches weekly (never `main`, `staging` or `assets/*`), and `website-preview.yml` deletes a PR's Cloudflare preview when the PR closes.
- Before an Expo SDK bump, run `npx expo install expo@^<sdk> && npx expo install --fix` in `apps/mobile`, then `npx expo-doctor`.
- Env files: each app commits `.env.example`; real values go in the gitignored `.env.local` (written by `scripts/env.ts`). Never commit keys.
- Cloud sessions: the SessionStart hook installs deps and, when `SUPABASE_DEV_*` vars are set, points the apps at the hosted dev Supabase project. Never point a session at production.

## Writing app copy

Covers every word a user reads: screen and row titles, subtitles, settings footers, empty and error states, alerts, permission prompts, notifications, onboarding, the website and the status page. Read the copy around the screen you are changing and match it.

- Lead with what the user gets. The title is the benefit, the body is the one thing to do plus anything that would worry them. Not what the app or iOS does behind the scenes.
- Say it once. Each sentence adds something new. Cut a line that restates the title or another line.
- Name the thing: "Nearby Menus", "your meal plan", "favorites". Never "this", "these features" or "all of these".
- No internals. Users never read about geofences, regions, background modes, sync, cache, OTA or the database. Use the words iOS shows them, such as the Always option for location.
- Keep it short. A title fits on one line, a body or footer is one or two short sentences, a row subtitle is a fragment with no period.
- Talk to the user as "you" and the app as "we", with contractions. Calm and friendly. An exclamation mark only for a warm moment, never in an error.
- State privacy as a plain fact ("Your location never leaves your phone."), not as a promise ("We take your privacy seriously.").
- Errors say what happened and what to do next, in words. Never show a raw error message, and never stop at "Something went wrong".
- Empty states say why it is empty and how to fill it. Loading never uses empty-state copy (see Conventions).
- Title Case for screen titles, settings rows, section headers and buttons (`Dark Mode`, `Remove from Meal Plan`). Sentence case for prompt and empty-state titles, subtitles, footers and alert text. Hours keep leading zeros (`09:00 AM`). No em dashes or arrows: write two sentences.
- A PR that adds or changes copy lists the new strings in its body so Ethan can review the wording.
